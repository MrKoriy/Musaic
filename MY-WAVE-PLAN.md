# «Моя волна» — состояние и план (актуализация 2026-09-23)

> Статус-документ: что уже работает, на чём построено, что дальше.
> Исполнимый бэклог — в `tasks.md`, исследования — в `RESEARCH.md`.

## Цель

Волна попадает в точку с первого трека: минимум ранних скипов, никаких
повторов и дизлайкнутого, мгновенная реакция на скипы/лайки в сессии.

## Целевые метрики (проверяются через `/api/recommendations/quality`)

- `earlySkipRate` по поверхности `my_vibe` < **0.15**
- `acceptedRequestRate` > **0.5**
- `canonicalRepeatRate` < **0.05**
- доля принятых треков от новых артистов ≈ **15%** (баланс 85/15)

## Что уже реализовано

- **Поверхности**: `my_vibe` (фильтры My Vibe), `auto_mix`, Daily Mix с
  персистентными версионными снапшотами, mood-чипы на главной.
- **Генерация кандидатов** (`reco/engine.ts`): библиотека + граф артистов
  (`jobs/artist-graph`), теги (`jobs/tag-backfill`), audio-эмбеддинги
  (`jobs/audio-embeddings`, опциональный sidecar), граф похожих треков
  (`jobs/similar-items`).
- **Профиль вкуса** (`reco/profile.ts`) + линейный ранжир (`reco/ranker.ts`) с
  обучением (`scripts/train-ranker.ts`, stratified CV, baseline и precision
  метрики в БД, миграции v14/v18).
- **Сессионная обратная связь** (`PlayerStore` → `stationRecentOutcomes`):
  outcomes (complete/skip/dislike) меняют скоринг прямо в сессии, seed-буфер
  исключает недавние треки, skip-streak ≥ 3 принудительно пересобирает станцию,
  дизлайк сразу выкидывает трек из выдачи.
- **Импрессии**: показы отслеживаются для оффлайн-оценки качества (v10).
- **Контроль качества**: `GET /api/recommendations/quality` — метрики выше по
  поверхностям и срезам.
- **Чат-рекомендации** (`reco/chat.ts`) поверх LLM (OpenRouter).

## Следующие шаги (по приоритету)

1. **«Почему этот трек»** — ranker уже считает вклад жанров/artist-affinity/
   разнообразия; отдавать топ-3 причины в ответе и показывать в UI волны.
2. **Кэш профиля с watermark** — профиль пересчитывается на каждый запрос;
   кэшировать с инвалидацией по последнему play event.
3. **Explore-quota 15%** — явная квота новых артистов в каждой волне со
   штрафом за ранние скипы экспериментов (регулируется настройками).
4. **Cold-start онбординг** — стартовый профиль из импорта/5–10 лайков вместо
   пустого профиля на свежей учётке.
5. **Grounded-чат** — ответы чата опираются на реальные фичи кандидатов из
   скоринга, а не на генерацию LLM «по памяти».
6. **Сезонность** — время суток/день недели как фичи ранжира.
7. **SSE-стриминг чата** — убрать ожидание полного ответа LLM (5–10 с).

## Инженерные правила

- Сервер: Bun + Hono + `bun:sqlite`; миграции БД — только новыми версиями в
  `server/src/db/migrations.ts`, применённые не редактировать.
- Меняешь поведение — добавляешь/обновляешь тесты в `server/src/__tests__`.
- Проверки: `cd server && bun run typecheck && bun test src/__tests__`.
- Метрики качества смотреть до/после изменения (не оптимизировать вслепую).
